# Expedition pacing and playstyle checks

The expedition now retains per-stage active-time milestones: first actual volley, first camp construction, first resolve damage, first casualty, and departure. It also totals resolve damage and casualties and observes time riding, guarding near camp, and travelling. Menus and closed-game time add nothing. Riding and guarding may overlap. Measurements start when an expedition begins; older saves start observing when loaded and do not invent missing history.

Read **Expedition milestones** in the chronicle's **Your clan** tab or in the results screen. Development console `metrics` prints the same observations; `benchmark` compares all four starting arrangements under three repeatable schedules without changing the current expedition. Both commands are read-only. Metrics persist in full saves; fresh expeditions and portable camp continuations start new measurements.

| Pressure-model schedule | Camp departure | Relative combat cadence                         | Risk/opportunity                                                               |
| ----------------------- | -------------: | ----------------------------------------------- | ------------------------------------------------------------------------------ |
| Aggressive riding       |     90 seconds | A defeat every 0.33 seconds after first contact | More XP and higher exposure while away from camp                               |
| Camp defence            |    125 seconds | A defeat every 0.45 seconds                     | Less camp exposure, recovery crafts and refugee arrivals; more food/time spent |
| Early migration         |     45 seconds | A defeat every 0.5 seconds                      | Shortest journey and less development; leaner survival margin                  |

`GAME.pacing` supplies the deterministic pressure model. `dev/pacingBenchmark.ts` uses the real economy, validated camp purchases, real migrations, destination modifiers, casualties, and arrivals over a fixed window of `GAME.pacing.maximumSeconds` active seconds. It applies explicitly modelled incoming contacts and defeat cadence drawing kills from `encounterEnemy` rather than pretending to simulate aiming, pathfinding or player skill. With no final stand, a run either survives the window or loses its clan; the twelve combinations are deterministic and each completes at least three migrations. Regression assertions compare kill rate, population and number of migrations so the schedules remain meaningfully different. Run `npx vitest run tests/unit/expeditionPacing.test.ts` or the console `benchmark` command.

The 45-second departure gate remains the common baseline. Starting arrangements supply measured resource/mobility/protection tradeoffs rather than locking a strategy. These smoke tests provide balance guardrails; live physical combat, the chosen terrain and longer player sessions still need comparison using the recorded metrics. A browser regression additionally observes an actual opening volley before 20 active seconds and verifies the chronicle presentation.
